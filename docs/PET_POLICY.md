# 桌宠后端方针(Pet Backend Policy)

> **本文是约束性文档。** 后续所有涉及「桌宠人格 / 对话 / 主动回复」的改动都必须遵守本文。
> 最近更新:2026-09(用户裁定)

---

## 一、产品方针

1. **单后端,双前端。**
   网页端聊天框与未来的桌宠前端**共用同一套后端 API**。网页端就是"桌宠对话框"的一种
   形态,不是另一套系统,不允许出现"网页专用"的分支逻辑。

2. **网页端 = 能对话 + 能主动回复的桌宠。**
   网页端必须承接桌宠的全部能力,**包括系统主动发起的话**,而不是只做被动问答。
   凡是桌宠前端将来要用的能力,网页端 API 必须已经具备。

3. **桌宠前端后置,后端不为它做特例。**
   未来桌宠前端只调用既有 API。新需求应当先落成"通用能力",再由前端消费;
   禁止为某个前端临时加旁路接口。

4. **能力缺口要补齐,而不是藏起来。**
   例:主动消息已进入 outbox,但网页端尚未展示——这属于**待补的能力缺口**,
   应当在网页端补上,而不是让主动关怀"只发不显示"。

## 二、人格方针:单一真相

- **角色卡是人格的唯一来源。**
  角色卡文件:`src/gzhu_cup2/agent/pet/character/<name>.json`(Character Card V2)。
  人格、世界观、说话风格、**主动回复提示词**全部来自卡。

- **角色卡 > config 内置默认值。**
  有卡则卡优先;没有卡(`PET_ACTIVE_CARD=""`)完整回落到 config 内置的纯助手设定
  (最纯净的 AI,无人格)。

- **禁止在 Python 里复制人格。**
  不得再出现 `_default_persona()` / `_default_world()` 这类"Python 与 JSON 各存一份"
  的双源真相 —— 改一处不影响另一处是历史事故的直接成因。

- **卡可切换。** 换卡 = 改 `PET_ACTIVE_CARD`;多卡 = 目录里多放文件。

## 三、提示词方针:写活,不硬编码

**要求:任何"构造给模型的话"的文本,都不得写死在业务代码里。**

判定标准(三条必须同时满足):

1. **可被角色卡覆盖** —— 卡里定义了就用卡的;
2. **代码默认里不得出现角色专名** —— 不许出现"团团""Sayori"等具体名字,
   一律使用 `{{char}}` / `{{user}}` 宏;
3. **代码默认只承担脚手架职责** —— 让系统在"卡没写全"时仍能工作,而不是充当人格本体。

### 唯一例外:安全项,刻意保留硬编码

| 保留在代码里的东西 | 位置 | 理由 |
|---|---|---|
| 危机热线文案 | `prompts/prompts.py` | 安全红线,不允许被角色卡关闭 |
| 主动消息禁词正则 | `care/content.py::_FORBIDDEN_PATTERNS` | 防止内部标记/临床术语外泄 |
| 危机关键词表 | `nodes/triage.py::_CRISIS_PHRASES` | 不能让配置文件关掉危机检测 |
| 应用侧硬规则 `HARD_RULES` | `prompts/prompts.py` | 角色卡的 `system_prompt` 只能追加在它之后 |

## 四、主动回复方针

1. **每一条主动消息都必须跑一次 LLM。**
   不存在"模板兜底直接发给用户"的路径。LLM 不可用或输出违规 → **本次静默丢弃**,
   由 `care.runtime.mark_blocked` 记冷却(不占当日额度、不入 outbox)。

2. **主动消息必须带人格。**
   语气、称呼、口癖、话题切入方式全部来自角色卡。

3. **决策与文本分离。**
   - "该不该说、说哪一类" = 纯函数决策逻辑,留在 `care/policy.py`(可单测、零 IO);
   - "具体怎么说" = 数据驱动,走角色卡的提示词配置。

4. **六类主动消息**(`care/policy.py::CareKind`)是**通用能力**,不是网页端专有:
   `checkin` / `recall` / `petlife` / `soothe` / `probe` / `warm`。

5. **未获回应要退避,但永不静默。**
   自用户最后一次发言起,每发出一条未获回应的主动消息,下一次的最小间隔按
   `CARE_UNANSWERED_BACKOFF_HOURS` 逐级拉长并**封顶**;同时不再发「提问型」
   (probe / recall / soothe),只保留「存在感型」(petlife / checkin);
   用户一说话即解封(coordinator 检测到"用户在最后一条已投递消息之后发过言"
   就清零计数)。

   - **为什么封顶**:间隔单调变长但有限 → 长期沉默的用户仍会定期收到一句。
     "未回应即永久停止"会让**不回话的人(恰恰可能是状态最差的人)被系统放弃**,
     这在心理健康产品上是危险方向。同理,"所有门槛都是 `gap >= X`"会导致
     **越沉默越发得勤**,方向也是反的。
   - **例外(不得被退避废掉)**:守护升温 `guard_elevated_after_distress` 分支
     排在退避 gate **之前**,用户状态不好时仍能穿透。
   - **只认已投递**:`last_delivered_ts` / `unanswered_streak` 只由 `mark_sent` 推进;
     `mark_blocked`(生成失败/命中禁词)不消耗退避次数 —— 否则"什么都没发出去"
     也会被算作已主动,极端情况下会造成永久静默。

6. **手动强制(force)只松时机闸,不松开关门。**(2026-10-26)
   用户在「桌宠今日记忆」面板点「让它现在说点什么」= 显式知情同意:
   `CareSnapshot.force=True` 跳过全部**时机闸**(免扰时段/每日上限/沉默门槛/
   晚安禁言/未回应退避/冷却),checkin 兜底无条件可用(保证必有一条消息的资格);
   **总开关、用户开关与打扰等级不被绕过** —— 勿扰等级下路由返回
   `blocked="quiet_mode"`,前端置灰并说明。消息生成与禁词过滤照常;
   手动消息走同一条 `mark_sent` 账本(计入每日额度与退避)。

7. **今日叙事是可见、可参与的生活,不是黑盒。**(2026-10-26)
   - 显示:`GET /api/pet/daily` + 设置「桌宠」页的「桌宠今日记忆」面板;
   - 刷新:`POST /api/pet/daily/regenerate`(显式丢弃当日条目重生成;
     默认**不限次数**(`PET_DAILY_MAX_REGENERATES_PER_DAY=0`;设正数才节流);
     停用 409;LLM 失败落 `unavailable` 当日不再自动重试);
   - 编辑:`PATCH /api/pet/daily`(零 LLM、`source="user_edited"`、
     截断到 `PET_DAILY_MAX_LEN`、不占刷新额度;刻意**不做输入侧禁词过滤** ——
     用户自己机器上编辑自己的桌宠素材,输出侧过滤照常兜底)。
   刷新与编辑后的文本同样经 `today_or_ensure` 成为 petlife 素材 —— 下游零特例。

   **素材边界（2026-10-26）**：叙事可读 `user_profile` 的称呼/likes/dislikes，
   但只作**素材**、不作指令；称呼只在需要时使用，likes 可自然提及，dislikes 只在自然相关时
   **轻轻带过**（不展开、不反复强调），不逐字复述。自由文本进提示词前
   折叠空白并限 120 字；`ticks` / `trend` / `guard` 仍不读 `user_profile`。

8. **用户自述 likes 只作「好奇钩子」的兜底，不天天问。**（2026-10-26）
   - 只在没有可回访的近期事实（`initiable_topics` 为空）时才启用；
     有近期事实时，事实优先。
   - 与 `recall` 共用文案通道，但单独频控 `CARE_PROFILE_LIKE_MIN_GAP_DAYS=7`；
     稳定偏好不是近况，不能问成日常打卡。
   - **只用 likes，不用 dislikes**：主动关怀不该主动提用户讨厌的东西。
   - 话题仍来自用户自述（可改可删），`ticks` / `trend` / `guard` 不读它。

9. **主动消息不能复读自己。**（2026-10-26）
   - 每次生成都带【你最近已经说过的话】与【距上次对话】两块上下文；
     "最近说过的话"存在 `care/runtime.py` 的 `recent_texts` 定长环里（5 条），
     **与 outbox 分开**——用户读完消息 outbox 会被 dismiss，但"已经说过"仍要拦。
   - 分档口径：距上次对话 <2 小时 → 顺着刚才的话说，**禁止**「好久不见 / 好久没见到你 /
     我一直都在」这类套话（用户刚说过话，这么说很假）；>1 天 → 才可表达想念，且要落到具体小事；
     深夜/清晨必须把时间说进去。
   - 代码兜底：开头 6 字与最近一条相同 → 带"换一个开场"提示重试一次
     （`care/content.py::generate_message`），仍撞车就接受重试结果。
   - **角度去重（2026-10-27）**：只看字面拦不住"换个说法说同一件事"。实测
     00:08「都过十二点了 还不困呀」→ 00:09「嗯？还醒着呀 我眼皮都快打架了」，
     开头完全不同、角度一模一样。现在按**角度**拦：最近**三条**用过哪个角度
     （目前登记 `熬夜/时间`，含"这个点"与任意钟点表达，如"零点半"），提示词里明写
     【本次不要用的角度】并声明**优先于** checkin 里"深夜要把时间说进去"的要求；
     生成结果仍落在该角度就重试一次，真的换了角度才采纳（宁可保留第一版，
     也不能点了按钮没反应）。
   - **接话素材（2026-10-27）**：主动消息会读「用户最后说的一句话」放进提示词，
     只作素材——顺着说一句人话，**不复述原句、不追问其中沉重/私密的部分**。
     三条硬边界：超过 `CARE_LAST_USER_MAX_AGE_MINUTES`（120 分钟）不引用；
     high/crisis 轮与负向分 ≥ `CARE_LAST_USER_MAX_NEG`（0.6）一律不引用；
     折叠空白后截断到 `CARE_LAST_USER_MAX_CHARS`（60 字）。总开关
     `CARE_REFER_LAST_USER`（关掉即回到 2026-10-26 的行为）。
   - **同一句话只接一次（2026-10-27）**：若上一条主动消息已经是在用户这句话之后
     发出的（`last_proactive_ts ≥ last_activity`），下一次就**不再引用**这句 ——
     实测连点三次全变成"你去忙，我等着"，同一句被接三遍也是复读。
     用户再说新的一句，接话资格自动恢复。
   - 手动触发也挡连点：`CARE_FORCE_MIN_GAP_SECONDS=60` 内返回 `force_too_soon`，
     避免 1 分钟内连发两条（实测过一次，用户看到的就是复读）。
   - 叙事要"有生活"：3-6 句、80-160 字，含具体场景/动作/感官细节与一个当下的心情或小念头，
     不总结、不抒情排比；`PET_DAILY_MAX_LEN=220`，petlife 单条上限放宽到
     `CARE_MESSAGE_MAX_LEN=320` 以装下叙事+邀约。

10. **主动消息必须进入"模型看的上下文"，而不只是"用户看的记录"。**（2026-10-27）
   - 落点：`sessions.deliver_proactive` 在写会话库之后，调用
     `engine.push_assistant_line(thread_id, text)`，把这句话以 `AIMessage` 补进
     该 thread 的图状态（`InMemorySaver`）。图还没建时直接跳过，不为了补上下文去建图。
   - 为什么：实测 13:32 主动消息说「等会儿念给你听呀」，用户回「好呀，跟我讲讲吧」，
     模型却答「那随便聊～ 今天中午吃了什么呀」—— 因为 `sessions` 里有的、`state["messages"]`
     里没有，模型根本不知道自己承诺过什么。对话因此整段前言不搭后语。
   - **不要用 `sessions` 反推历史**：图的状态才是模型的短期记忆；两处必须同时写。
     这也意味着**重启进程后短期对话记忆会丢**（既有行为，与主动消息无关）。

11. **用户在场时，手动触发的消息不摆「主动消息」卡片。**（2026-10-27）
   - 判定：`since_minutes ≤ CARE_INLINE_CHAT_MINUTES`（默认 10 分钟）→ `msg["inline"]=True`，
     `deliver_proactive` 落库时 `kind` **仍然是 `"proactive"`**，只是多带一个
     `inline=True`；前端据此显示「主动搭话」这种轻量标注，不摆「主动消息 · 问候」卡片。
   - **绝不要把 `kind` 改写成 `"chat"`**（同日踩过）：chat 轮的语义是"用户说一句 +
     AI 回一句"，inline 消息没有用户那一侧，写成 chat 会让前端渲染出一个空的用户气泡 ——
     用户看到的是对话流里凭空一个空格，而且"是它先开口"的标记整个消失。
     `kind` 只表达"这一轮谁发起"，是否摆卡片交给 `inline`。
   - 历史脏数据（`kind="chat"` + `user` 为空 + 有 `care_kind`）由
     `sessions._repair_legacy_inline_proactive_locked` 在加载时一次性修正并落盘；
     真实聊天轮次永远有用户输入，不会被误伤。
   - 为什么：正在聊天时再插一张「主动消息 · 问候」，接着又来一句「好好好 来了来了」，
     用户看到的不是关心，是它忽然"又出现了一次"。
   - 自动路径事实上打不到这个窗口（`CARE_MIN_USER_SILENCE_MINUTES=30` 已经挡住），
     所以这条主要约束**手动触发**。

12. **主动消息要知道自己刚在对话里说过什么。**（2026-10-27）
   - 素材：`coordinator._my_last_line()` 取最近一小时内、桌宠在**对话里**说过的最后一句话
     （来自 `store.recent_turns` 的 `ai` 字段，主动消息本身不在其中），
     作为【你刚才在对话里说过】注入提示词，并附"不要再重新来一遍"。
   - 为什么：上一句已经念过诗，下一条主动消息却说「来了来了 就是那首太短了」——
     它会"接着自己没说过的话往下演"。修复后实测变成「已经念了呀！就那句嘛」。

## 五、首启引导不是「主动回复」

6. **第一次见面问的三件事是产品引导,不受第四节约束。**
   「称呼 / 喜欢的事物 / 讨厌的事物」由 `core/user_profile.py` 存储、桌宠首启时提问
   （`apps/desktop/src/App.vue`），它**不是** care 的主动消息:

   - **文案静态、不走 LLM** —— 首次启动时 API Key 大概率还没配，走模型必 503；
     这不算违反"每条主动消息都必须跑一次 LLM"(那条只针对 care 的关怀消息)；
   - 不入 outbox、不占 `CARE_MAX_PER_DAY`、不参与退避，也不受免扰时段拦截；
   - **可跳过**：跳过写 `onboarding.dismissed_at`，之后**永不重复询问**；
     未跳过也最多问 3 次(`MAX_PROMPT_TIMES`) —— 引导不能变成骚扰；
   - **清空记忆不重置引导状态**：`user_profile.clear()` 只清三项内容，留下
     `dismissed_at` / `completed_at` / `seen` —— 跳过是用户的明确答复，
     不能因为他清过一次数据就作废（否则「永不重复询问」是句空话）；
   - 答案只用于称呼(`{{user}}` 宏)与生成提示词的话题参考，
     **不进 `ticks` / `trend` / `guard`**：用户自述不是风险信号（「单信号不触发」）；
   - 引导接管启动气泡时**必须补放角色卡开场白**：随包会投放一张初始卡并默认启用
     （`main.cjs::seedInitialCard`），不补放就等于把 `first_mes` 永久吞掉
     （`App.vue` 的 `closeOnboarding`）。
